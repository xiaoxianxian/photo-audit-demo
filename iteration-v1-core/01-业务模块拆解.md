# 01-业务模块拆解（v2：供稿 + 直播 + 短视频）

## 背景

原 MVP 仅支持图文供稿审核（单文件 index.html）。本次重构需要支持：
- **供稿（图片）**：传统 UGC 图片上传审核
- **短视频**：视频文件上传，AI 抽帧 + 音频 ASR 审核
- **直播**：实时推流，定时截帧，审核员电视墙实时监控

日均处理量：**千万级供稿 + 直播截帧 + 短视频**，100 人审核团队。

---

## 模块一：内容接入与预处理（Content Ingestion）

**做什么：** 接收来自各渠道的内容（图片上传、视频上传、直播推流），做格式校验、预处理（缩略图/封面/抽帧/ASR 转写），生成待审元素。

**类比：** 快递站的「收件 + 分拣窗口」。不同形态的包裹（图片/视频/直播流）进来，先检查外包装（格式校验），再拆开分类（元素拆分），贴上标签（元数据），放进对应的传送带（审核队列）。

**关键职责：**
- 供稿图片：拖拽/批量上传 → 缩略图生成 → 元素拆分（封面图、图片本体）
- 短视频：文件上传 → 封面抽帧 → 音频 ASR 转写 → 元素拆分（封面图、视频片段、转写文本、标题、评论）
- 直播：接收 RTMP/WebRTC 推流 → 按间隔截帧（默认 15s）→ 元素拆分（截帧图、直播间标题、实时评论）
- 对象存储：MinIO 存储原文件 + 预处理产物
- 异步队列：RabbitMQ/Kafka 承接峰值流量，削峰填谷

---

## 模块二：AI 机审引擎（AI Review Engine）

**做什么：** 接收待审元素，调用对应的 AI 模型进行多维度分析，输出结构化审核结果。

**类比：** 工厂里的「多工种质检流水线」。图片交给视觉模型，文本交给 NLP 模型，音频交给 ASR 模型，最后汇总成一个综合风险分。

**关键职责：**
- 多模态路由：
  - 图片元素 → 视觉模型（Gemini/GPT-4o/Kimi）→ 色情/暴力/敏感标识/画质
  - 文本元素（标题/评论/ASR 转写）→ NLP 模型 → 敏感词/情绪/政治
  - 视频元素 → 抽帧走视觉 + 音频走 ASR → 汇总
  - 视频查重 → 指纹比对（simhash/perceptual hash）
- 裁判模型：DeepSeek 对主审结论做逻辑一致性校验，分歧结果标记展示给人审参考
- 统一输出格式：`{ risk_score, risk_types[], confidence, reason }`
- 额度/频率控制：自动降级、模型切换
- 审核结果异步入库

---

## 模块三：人工审核工作台（Human Review Dashboard）

**做什么：** 审核员看到 AI 初审结果，执行审核操作。支持三种视图：

**类比：** 审核员的「办公桌」，但有三块屏幕：一块看静态图片/视频，一块看直播电视墙，一块看数据看板。

**关键职责：**
- **供稿审核视图**：卡片网格，AI 评分 + 机审标签 + 操作按钮（通过/打回）
- **直播电视墙**：多路直播缩略图实时刷新，每个格子标 AI 风险分，点击可查看详情/历史截图/转写文字/实时评论，即时处置（切断/警告/标记）
- **短视频审核视图**：播放器 + 转写文字 + 评论列表 + AI 风险标签
- 通用能力：
  - 筛选/排序（按风险分、按时间、按租户、按元素类型）
  - 批量审核
  - 审核操作：通过 / 打回（带原因分类 + 判罚等级）
  - 审核状态机：`pending → approved / rejected / appealed`
  - 裁判分歧高亮提示

---

## 模块四：申诉与改判闭环（Appeal & Rectification）

**做什么：** 用户申诉被拒内容 → 系统记录 → 专人审核 → 维持原判或改判解封 → 通知用户。

**类比：** 客户的「售后通道 + 客服改判」。摄影师/主播觉得被误判了，提交申诉。专门的审核员复核，维持或推翻原判。改判后自动触发通知。

**关键职责：**
- 申诉表单（内容摘要 + 申诉理由 + 证明材料）
- 申诉状态追踪：`rejected → appealed → under_review → resolved_approved / resolved_maintained`
- 改判日志（append-only，不可篡改）
- 质检/抽检发现误判 → 主动改判

---

## 模块五：质检与抽检（Quality Assurance）

**做什么：** 质检组定期回溯已审核内容，评估审核质量和系统效果。

**类比：** 工厂的「品质管理部」。不是直接审内容，而是抽查已经审过的内容，看看审核员审得对不对、AI 准不准。

**关键职责：**
- 质检批次：选定一批历史任务，重新审一遍
  - 修正模式：仅修正内部记录，或连带修正用户判罚
- 抽检任务：圈定某段时间/某租户的任务，重新人审，计算准确率、召回率、风险水位
- 审核员绩效：按审核量、准确率、平均耗时统计

---

## 模块六：租户管理与配置中心（Tenant Admin & Configuration）

**做什么：** 多层级用户管理 + AI 模型配置 + 审核规则 + 业务看板。

**类比：** 控制室的「总仪表盘 + 权限管理中心」。

**关键职责：**
- **租户体系**：平台超管 → 租户管理员 → 审核员/质检员三级 RBAC
- **审核团队管理**：团队创建、成员增删、角色分配（普通/高级/质检）
- **AI 模型配置**：API Key 管理、模型切换、额度监控
- **审核规则配置**：预设模板 + 租户自定义敏感词 + 规则表达式
- **判罚等级配置**：用户级（冻结/封禁）+ 功能级（冻结直播/评论）+ toast 警告
- **业务看板**（真实计算 + mock 占位）：
  - 今日已审、平均出审时效、机审召回率、通过率趋势
  - 直播电视墙在线数、短视频审核积压量
  - 审核员绩效排名
