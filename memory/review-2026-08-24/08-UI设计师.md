## 一、做得好的地方 👍

1. **设计令牌体系完整**：`constants.ts` 作为单一来源（COLORS/SPACING/FONT/RADIUS/SHADOW/ANIMATION），绝大多数页面从令牌取值而非魔法数字，深色 GitHub Dark Dimmed 调色板统一。
2. **键盘效率设计有成体系的思考**：`←→` 导航、`Space/Enter` 通过、`Esc` 打回，且有**实时快捷键提示条**（显示“当前第 N/M 项”），HelpModal 内置快捷键速查。
3. **防审核疲劳机制**：连续通过 ≥5 次时 Popconfirm 文案动态升级为警告（“连续快速通过可能增加误审风险”），这是审核台少见的细节。
4. **空态区分场景**：Review 页空态区分“筛选条件导致为空 → 提示调整筛选”vs“真的没数据 → 引导上传”，优于多数 demo。
5. **实时状态可视化**：WS 连接状态 Tag（● 实时连接/○ 离线）、新任务计数可点击刷新、电视墙 10s 兜底轮询。
6. **裁判分歧强提示**：橙色 `#fa8c16` 2px 边框 + “分歧”Tag + Tooltip 三重编码（色彩+图形+文字）。
7. **加载骨架屏**：CardSkeleton/TableSkeleton/StatsSkeleton 组件化，且骨架布局模拟真实卡片结构。
8. **可访问性基础**：`*:focus-visible` 全局焦点环、大量 `aria-label`、密码强度 checklist 带 ✓/○ 双通道指示。
9. **图片容错**：ElementCard 有 base64 fallback + onError 手写“预览不可用”。

### B. 视觉一致性

- **两套间距/圆角/字号令牌并存**：`SPACING` vs `GUTTER`（sm=16/base=16 重复）、`global.css` 的 `--pa-*` CSS 变量与 TS 常量重复定义（改一处漏一处）、`.pa-h2`(2rem) 与 `FONT.h2`(32px) 两套字号体系。
- **文字层级命名反直觉**：`textTertiary #c9d1d9` 比 `textSecondary #8b949e` **更亮** —— tertiary 语义应为更弱，实际更强，多处正文用 tertiary、辅助信息用 secondary，层级随机。
- **标题字号混搭**：`Title level={3}` 强配 `fontSize: FONT.h2(32px)`（Layout/Login/Register），antd 语义等级与实际像素脱钩。
- **QualityAudit.tsx:342** 抽检表单用原生 `<input type="checkbox">`，与其余全 antd 组件风格割裂。
- **组件命名误导**：`BatchDetailDrawer` 实际是 Modal；`Content` 从 Layout re-export 导致每个页面 `import AppLayout, { Content }` 的非常规模式。

### C. 响应式问题

- **Login 卡片 `width: 400`、Register `width: 480`、SubmitAppeal `width: 560` 固定宽**，视口 <480px 时水平溢出（应 `width:'100%', maxWidth`）。
- **Sider 无 `breakpoint` 收缩**：240px 侧栏在移动端永久挤压内容区，Menu 无 collapsed 模式。
- Review 卡片网格 `xs=24 sm=12 md=8 lg=6` 合理，但**卡片内容高度不等**（文本元素 vs 图片元素 120px），同行卡片底部不对齐，网格观感参差。
- Dashboard 趋势“图”实为逐行横条列表（每行一条 date+bar），7 天占约 7×~150px 高度，信息密度极低，不像趋势图更像表格。

### D. 深色主题对比度与可访问性

- **LiveWall 风险分浮层**：`riskColor()` 的 success 绿底 `#3fb950` 上放浅色字 `#e6edf3` —— 对比度约 2:1，**不达标**（WCAG AA 需 4.5:1）；warning 黄底同理。
- **离线 tile 整体 `opacity: 0.5`**：文字对比度再砍半，OFFLINE 标签几乎不可读；应降饱和而非降透明度。
- **置信度旁用 `UserOutlined` 用户图标**（LiveWall:161）—— 语义完全错位，用户图标≠置信度百分比。
- `global.css` `.ant-btn:hover { opacity: .9 }` 无差别作用于所有按钮（含 danger/disabled）；table hover `rgba(255,255,255,.04) !important` 硬编码覆盖主题变量。
- 图标-only 按钮（Dashboard/Appeal/TenantConfig 操作列）依赖 Tooltip 提供名称，Tooltip 的 title 不等于可靠的可访问名，部分按钮缺 `aria-label`。

## 三、审核工作台效率设计专项 🔍

1. **Esc = 直接打回（不可逆操作绑单键）**：`handleReject(id, '快捷键打回')` 无二次确认、无撤销，与鼠标路径（Popconfirm 确认）安全等级不一致 —— 误触 Esc 即产生一条打回记录。建议 Esc=取消选择/关闭弹层，打回走显式键（如 X）+ 可撤销 toast。
2. **批量打回原因写死 `'批量打回'`**：单条打回有原因分类 Select，批量却没有 —— 数据侧打回原因统计会被污染，交互也不对称。
3. **快捷键仅在“聚焦某张卡”后生效**（focusedIndex≥0），初始进入页面按 Space/Enter 无效且无提示如何开始聚焦；`onFocus` 绑在整卡 tabIndex 上，鼠标点击卡内按钮也会改变焦点语义。
4. **卡片密度偏低**：lg 断点一行 4 张、图片仅 120px 高，对“扫图判违”场景太小；审核主图建议 ≥200px 或提供密度切换（紧凑/舒适）。
5. **上传区常驻页面顶部**（Dragger 大块头）：审核工作台的主体是“审”不是“传”，Dragger 应收纳为按钮或折叠条，还出一行卡片的纵向空间。
6. **QualityAudit 抽检样本只显示 kind+风险分，不展示内容本体** —— 抽检员不给看图/文就无法给出抽检分，这是质检流程的硬伤。
7. **操作后无 undo**：所有审核动作只有 message.success，高危打回/批量操作缺“已打回 · 撤销”式反馈。
8. **ShortVideoReview 元素抓取**：`getPendingElements({page_size:100})` 拉全量再前端过滤 content_id —— 超 100 条即丢数据，应传 content_id 过滤参数。

## 四、三态与反馈设计

- **加载态**：Review/Dashboard 骨架屏 ✅；但 AIConfig loading 只有一行文字“加载中...”；Appeal 详情 Modal 内手写重复的骨架 div（应复用 SkeletonBlock）。
- **错误态**：全部依赖 `message.error()` 一闪而过，无页面级错误重试入口；fetch 失败后 elements 置空数组 → 用户看到的是“暂无待审元素”空态，**错误态被伪装成空态**（误导性强）。
- **反馈及时性**：✅ 所有 mutation 都有成功/失败 toast、按钮 loading；❌ LiveWall 点击高风险跳转 `/review` 后 Review 页并未消费 `state.fromLiveWall` 参数（跳转意图丢失）；WS 断线无重连逻辑（onclose 空实现），与 CLAUDE.md 承诺的“自动重连”不符。

**P2（增值）**

11. HelpModal 风险图例与 `riskTagColor()` 从同一常量生成，杜绝两处漂移。
12. 统一 rejectOptions 到 constants（现在 Review 与 ShortVideoReview 各维护一份，且选项不同：一个有“画面模糊”、另一个是“内容低质”）。
