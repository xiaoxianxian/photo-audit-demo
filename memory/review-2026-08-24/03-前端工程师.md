## 一、做得好的地方

1. **路由层设计干净**：全部页面 `lazy()` 代码分割 + 统一 `Suspense` fallback；`ProtectedRoute` 用 `useAuthStore((s) => s.user)` 精确选择器订阅，避免整 store 重渲染；按角色守卫（tenant-config / ai-config / quality-audit）与 RBAC 设计一致。
2. **设计令牌集中**：`utils/constants.ts` 单一来源（COLORS/SPACING/FONT/RADIUS/风险分阈值与 helper），`riskColor/riskLabel/riskTagColor` 三档阈值统一，杜绝了魔法数字散落。
3. **审核工作台的领域细节到位**：裁判分歧橙色高亮（`is_conflict`）、连续通过 ≥5 次的防疲劳确认（Popconfirm 文案变化 + 快捷键拦截）、WebSocket 新任务角标 + 手动刷新按钮、离线状态提示——这些是真实审核业务才会想到的细节。
4. **键盘快捷键体系存在且有帮助文档**（HelpModal 列出快捷键）、卡片有 `tabIndex=0 role="button" aria-label`、图片有 `fallback` SVG 占位和中文 alt、空态区分“有筛选→调整条件 / 无筛选→去上传”——无障碍和空态意识明显高于 demo 平均水平。
5. **Zustand 用法正确**：`persist` + `partialize` 只持久化 token/user，不把函数序列化进去；请求拦截器用 `useAuthStore.getState().token` 取值而非 hook，避免了循环依赖。
6. **LiveWall 有降级策略**：WS 推送 + 10s 轮询兜底双通道，符合 CLAUDE.md “断线补偿” 的设计意图。

## 二、Bug（按严重度排序）

### 🔴 B1. Dashboard「添加团队成员」表单完全失效
`TeamModal` 只有一个 `form = Form.useForm()` 且只绑定到「新建团队」分支的 `<Form form={form}>`；`add-member` 分支的 `<Form<{user_id; role}>>` **没有绑定任何 form 实例**。`handleSubmit` 里 `form.validateFields()` 校验的是空的新建团队表单 → 立即 resolve `{}` → `onSubmit({})` → `handleTeamSubmit` 中 `payload.user_id` 为 undefined → **两个分支都不执行，Modal 关闭，无成功也无失败提示**。用户以为添加成功了，实际什么都没发生。（Dashboard.tsx L302–372, L603–618）

### 🔴 B2. Review 页 Esc 键 = 无确认直接打回，且与 Popconfirm 冲突
`handleKeyboardShortcut` 中 `Escape → handleReject(id, '快捷键打回')`。两个问题叠加：
- 打回是“不可撤销”操作（自家 Popconfirm 文案承认），却绑在最常用于“取消/关闭”的 Esc 上且零确认；
- 当焦点卡片上打开了打回 Popconfirm，用户按 Esc 想**取消弹窗**时，全局监听会**同时把该元素打回**。“想取消却执行了不可撤销的拒绝”是审核场景最危险的交互事故。

### 🔴 B3. 批量选择状态跨页/跨筛选泄漏
`selectedIds` 在翻页、改筛选、排序时**从不重置**。用户在第 1 页勾选 5 项 → 翻到第 2 页 → 批量栏仍显示“已选择 5 项”，此时点批量通过会把**看不见的第 1 页元素**一起通过。另外 `toggleAll` 用 `prev.size === elements.length` 判断反选，选中集合含跨页 id 时判断失真，“全选”勾选态也会错乱。

### 🟠 B4. WebSocket 回调闭包过期（stale closure）
Review.tsx 的 WS effect 依赖 `[token, user?.tenantId]`，但回调里引用的 `fetchElements/fetchStats` 是**首渲染闭包版本**——用户改过筛选条件后，WS 推送的 `new_task` 触发的刷新仍用旧参数请求，列表会被旧筛选结果覆盖。应将最新 fetch 存入 ref 或把 fetch 函数加入 effect 依赖并处理好重连。

### 🟠 B5. 分页 pageSize 失控
`Pagination {...TABLE.pagination}` 展开了 `showSizeChanger: true`，但组件里 `const [pageSize] = useState(20)` **没有 setter**，也没传 `onShowSizeChange`。用户切到 50/页 → UI 变了、请求还是 20 → 数据与分页器不一致。

### 🟠 B6. HelpModal 文档与实现不符
HelpModal 明确列出「Shift + Enter = 批量通过已选元素」，但 Review.tsx 全文**没有任何 shiftKey 处理逻辑**（已 grep 验证）。文档承诺的快捷键不存在。

### 🟠 B7. api.ts 的类型在运行时不成立（两处谎言）
```ts
async function request<T>(config): Promise<T> {
  const wrapper = await axiosInstance.request<ApiResponse<T>>(config);
  return wrapper.data as T;
}
```
响应拦截器已返回 `response.data`（即 `ApiResponse` 包裹体），所以 `axiosInstance.request<ApiResponse<T>>` 的泛型声明是错的，靠 `as T` 强转掩盖。同理 `humanReview/batchReview/updateContentStatus` 等 `return axiosInstance.post(...)` 声明 `Promise<void>`，**实际 resolve 的是 `{code,message,data}` 包裹体**。目前恰好能用，但任何人信任签名写 `res.data.data` 就会踩坑。建议仿照 content-api 的 unwrap 模式统一，或给实例做正确的类型重载（`axiosInstance.get<T> 返回 ApiResponse<T>`）。

### 🟠 B8. 401 处理用硬跳转且会在登录页自触发
`window.location.href = '/login'` 整页刷新丢失所有前端状态；且登录接口本身返回 401（密码错误）时也会触发 `logout() + 跳转`——登录页跳登录页，体验怪异。应排除 `/auth/login|register`，SPA 内用 `navigate` 并带 `redirect` 参数。

### 🟡 B9. antd `Tag color="info"` 不是合法预设值
antd 5 的 Tag 语义色只有 `success / processing / error / warning / default`。Review 统计条 `<Tag color="info">待审…</Tag>` 会静默回落为默认灰样式，“待审”这一最重要的数字失去了预期的蓝色强调。（AIConfig/TenantConfig 若同样使用请一并排查）

### 🟡 B10. LiveWall 的死代码与半成品防御
- `wsRef` 赋值后从未读取；`isMounted` ref 设置后从未使用；
- `cancelledRef` 只防 setState，不防请求本身（无 AbortController）；
- CLAUDE.md 承诺“WebSocket 断线自动重连”，实现里 `ws.onclose = () => {}` 是空的，**没有任何重连**，断线后只剩轮询且用户无感知（连离线提示都没有，对比 Review 页有连接状态 Tag）。
- 每 10 秒轮询都 `setLoading(true)`，空墙场景 Empty 提示会随 loading 抖动闪烁。

### 🟡 B11. 双重触发风险：快捷键 Enter 与原生按钮点击
全局 keydown 只排除了 `INPUT/TEXTAREA/SELECT`，未排除 `BUTTON`。当焦点在某个按钮（如 Popconfirm 的“确认通过”）上按 Enter 时：原生 click 与全局 handler（若 focusedIndex 有效）**同时各执行一次通过**，可能对同一元素产生重复审核记录。

### 🟡 B12. 登录错误提示暴露技术细节
Login 的 catch 里 `err instanceof Error ? err.message : ...`——axios 错误的 message 是英文的 `Request failed with status code 401` 直接弹给审核员。应在拦截器层归一化错误（读取后端 RFC7807 的 message），页面只展示人话。

## 四、性能

1. **🔴 图片加载最大的优化点被浪费了**：`ContentElement.thumbnail_url?: string` 字段存在但**从未使用**，Review 卡片网格和 ShortVideoReview 视频帧列表直接 `<img src={element.element_content}>` 加载**原图**。一屏 20 张原图（可能几 MB/张）在网格里 objectFit:cover 只显示 120px 高——这是审核工作台最痛的性能问题。改用 `thumbnail_url ?? element_content` + `loading="lazy"` + `decoding="async"`，收益立竿见影。
2. **ElementCard 内联 style hover**（onMouseEnter/Leave 直接改 `style.transform/opacity`）：每次 hover 触发 DOM 写 + 脱离 React 管理；应改为 CSS class/:hover 或 antd Card 的 hoverable 样式。同样的手写 hover 模式在 LiveWall StreamTile、QualityAudit 样本列表重复出现三处——抽一个共用样式。
3. **keydown 监听每渲染重挂**：`handleKeyboardShortcut` 依赖 `handleApprove/handleReject`（非 useCallback）→ 每次 render 都 remove/add listener。功能正常但属典型反模式；把 handler 放进 ref 或用 `useEffectEvent` 思路收敛。
4. **Dashboard 趋势图 O(n²)**：`Math.max(...dailyTrend.map(...))` 写在 map 循环体内，n=7 无所谓，但这是 code review 必提的坏味道，提到循环外即可。
5. **CardSkeleton 放错容器**：`<Row><CardSkeleton count={6} /></Row>` —— skeleton 渲染的是裸 div 数组，不是 `<Col>` 子元素，gutter 布局与真实卡片不一致，loading→内容切换时会跳动（CLS）。
6. **列表 key 本身没问题**（都用稳定业务 id 👍），但 LiveWall 每次 `snapshot_update` 就整页 `fetchStreams()` 全量替换数组，20+ 路 stream 时所有 Tile 重渲染；快照 URL 不变时应做浅比较跳过 setState，或按 stream.id 增量合并。
7. 未使用 `React.memo` 于 ElementCard/StreamTile——配合第 6 点，父组件任一 state（如 focusedIndex 移动）会导致整墙卡片重渲染。

## 五、用户体验

1. **上传流程反馈断层**：视频上传成功提示“正在抽帧和转写”后就没了下文——没有进度、完成后不主动通知（WS 已具备推送能力却不用在这里）；大文件 100MB 上传只有一个 `Spin`，无百分比进度（axios onUploadProgress 现成可用）。
2. **StreamTile 点击行为隐晦**：仅当风险分 >60 时点击才跳转审核页，低风险直播点了毫无反应、也无 cursor 提示差异——要么都能点，要么加 Tooltip 解释。
3. **复制 RTMP 无失败处理**：`navigator.clipboard.writeText` 未 await/catch，非 HTTPS 或权限拒绝时静默失败甚至 unhandled rejection，还先弹了“已复制”的成功提示。
4. **Dashboard 团队负责人下拉造假**：`leaders` 就是当前登录用户自己一个人，placeholder 却写着“搜索用户…”——演示可以，上线前必须接真实用户列表接口。
5. **Table `sorter: true` 是空头支票**：TenantTable 名称列声明了服务端排序标志，但没有传 onChange 处理也没有远程排序参数——点击排序箭头毫无反应。
6. **登出无确认、无跳转**：Layout 的退出按钮直接 `logout()`，留在当前路由（受保护路由随后踢到 /login，行为碰巧正确但属于巧合链）；建议显式 navigate('/login')。
7. **快捷键门槛**：快捷键仅在 `focusedIndex >= 0` 时生效，而进入聚焦状态的唯一途径是鼠标点击卡片或 Tab 到卡片——纯键盘用户 Tab 到卡片后 `onFocus` 设 idx ✅ 这点是对的，但帮助入口（右下角悬浮按钮）本身不在 Tab 序列早期，可发现性弱。建议首次进入 Review 页 toast 一次快捷键提示。

## 六、无障碍（a11y）

**好的**：aria-label 覆盖面广（表单、图标按钮）、图片有 alt、暗色主题对比度基本达标（textSecondary #8b949e on #161b22 ≈ 4.9:1）、Modal 有 zh_CN locale。

**需改进**：
1. **QualityAudit 待抽检样本列表**：可点击 `<div onClick>` 无 `role="button"/tabIndex/onKeyDown`——键盘用户完全无法抽检，与 Review 页的高标准形成反差；其中的原生 `<input type="checkbox">` 也应换成 antd Checkbox 保持一致性。
2. **ElementCard `role="button"` 但激活语义混乱**：卡片本身可聚焦、Enter 却走全局批准逻辑而非“打开详情”，屏幕阅读器会把它朗读成按钮但不明确按下后果；建议 aria-label 补充操作说明，或拆分“预览区”与“操作区”的可聚焦性。
3. **WS 连接状态仅靠颜色/圆点区分**（● 实时连接 / ○ 离线）：色弱用户无法分辨，好在有文字标签 ✓；但离线时无任何 Alert 提醒“数据可能不是最新的”。
4. **趋势图纯 div 条形**：无 `role="img"`/aria 描述，数据只在 `title` tooltip 里——触屏和读屏用户拿不到通过率/驳回率。

## 七、架构层面建议（优先级排序）

1. **引入 TanStack Query（或 SWR）**：全项目 12 个页面手工重复 `loading/error/setState/useCallback/useEffect` 五件套约 20+ 次，B3/B4 一类竞态和陈旧闭包大多源于此。Query 的缓存、失效、重试、竞态消除能一次性解决，Review 页还能免费获得 `keepPreviousData` 平滑翻页。
2. **全局 ErrorBoundary（已知缺失）**：当前任何一个页面渲染抛错 = 白屏。至少包一层路由级 boundary + 一个 `fallbackRender` 带“返回首页”。配套建议加 `vite-plugin-sentry` 或轻量 window.onerror 上报。
3. **API 层收口**：统一 `unwrap`、统一错误归一化（拦截器里把 AxiosError → `{ code, humanMessage }`）、从 OpenAPI 生成类型，三个动作做完，T1–T6 全部消失。
4. **WebSocket 抽成 `useWebSocket(url, { onMessage, reconnect: true })` hook**：现在 Review 和 LiveWall 两份相似但质量参差的实现（一个带 token 鉴权和状态提示，一个裸连且无重连），且端点风格还不一致（`/api/v1/review/ws` vs `/ws/live-wall`）——顺手核实哪一个才是后端真实路由。
5. **token 存储**：localStorage 存 JWT 有 XSS 面向风险，demo 可接受，生产建议 httpOnly cookie + CSRF，或至少加 token 过期时间解析与提前刷新。
6. **杂项清理**：删除 `.fuse_hidden*` 与 `.DS_Store`（加入 .gitignore）；`LIGHT_COLORS` 目前疑似死代码；`FONT.small` 注释写成 `--font-size-mono` 的笔误；`formatDate` 在 utils 有一份、Dashboard 又本地实现一份，收敛到一处。
